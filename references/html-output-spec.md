# HTML 输出规范

目标是生成可直接打开、内容完整、与受众匹配的单文件图文解释，而不是统一模板换色。

## 文件与交付

- 输出完整 HTML5 文档，包含 `<!doctype html>`、`lang="zh-CN"`、字符集、viewport 和准确标题。
- CSS 和必要 JavaScript 写在文件内，避免构建步骤。
- 优先保证单文件可用。若使用外部图片或字体，必须有合理的加载失败回退，不能让页面核心内容消失。
- 交付时优先创建 `.html` 文件并提供预览；环境无法创建 artifact 时，返回一个完整 `html` 代码块。
- 页面打开后直接进入解释内容，不制作产品宣传页、功能介绍页或无关欢迎页。

## 内容结构

页面不必机械使用相同区块，但应覆盖：

1. 主题名称和一句话本质。
2. 一个与受众匹配的核心类比。
3. 工作过程、因果关系或组成部分的图解。
4. 至少一个具体例子。
5. “这对你意味着什么”或可记住的结论。

复杂主题应采用渐进披露：先给核心结论，再允许读者展开细节。不要把所有文字塞进首屏。

## 图像与图解

- 视觉必须帮助理解真实概念，例如流程、层级、关系、状态变化、空间结构或前后对比。
- 有合适的图片生成或图片搜索能力时，可以使用与主题直接相关的位图素材。
- 单文件便携性更重要或没有图片工具时，使用内联 SVG、CSS 图解、图表、时间线或示意场景。
- 不使用纯装饰性的渐变球、光斑、无含义插画或与主题无关的库存图片。
- 不用大段可见文字解释页面怎么操作，也不把快捷键和设计说明写进页面。

## 视觉设计

- 页面风格由受众决定，不能所有年龄都沿用 5 岁绘本风格。
- 配色至少包含中性色、主色和功能性强调色，避免整个页面只由单一色系组成。
- 卡片圆角不超过 8px，除非主题本身有明确理由。
- 不把卡片嵌套在卡片中；页面章节使用自然流式布局或全宽区段。
- 控制标题尺度。只有页面主标题使用展示字号，面板、侧栏和图解内部使用紧凑字号。
- 字号不随 viewport 宽度线性缩放；使用明确的响应式断点和稳定尺寸约束。
- 固定格式元素使用 `aspect-ratio`、网格轨道或 min/max 约束，避免内容变化导致布局跳动。
- 正文字距为 `0`，保证中英文混排清晰。

## 交互

只有交互能改善理解时才添加，例如逐步演示、模式切换、时间线播放、前后对比或术语展开。

- 使用按钮、标签页、分段控件、滑块等符合用途的控件。
- 图标按钮需要可访问名称或 tooltip。
- 所有核心信息在 JavaScript 失效时仍应可阅读。
- 不添加无目的动画；动效应表示过程、因果或状态变化，并尊重 `prefers-reduced-motion`。

## 可读性与可访问性

- 使用语义化标题、段落、列表、图注和控件。
- 文字与背景保持足够对比度，不能把正文放在难以辨认的图片区域。
- 键盘可以访问交互控件，焦点状态清晰。
- 图像和图解提供有意义的替代文本或文字说明。
- 桌面和手机宽度下不得出现文字遮挡、横向溢出或控件重叠。

## 语言

- 除必要技术术语、代码、命令、API 名称和错误原文外，界面文字全部使用简体中文。
- 技术术语首次出现时给出简短解释，不连续堆砌中英文括号。
- 页面中不出现“这是一个 ELI5 页面”“本页面采用某种设计”等自我描述。

## 完成检查

- 直接打开文件，确认没有空白页、缺失核心视觉或脚本错误。
- 至少检查一个桌面尺寸和一个手机尺寸。
- 核对最长标题、代码、术语和按钮文字没有溢出。
- 确认视觉元素确实解释了主题，而不是只起装饰作用。
- 核对年龄、职业或关系对应的文字难度与视觉风格都已生效。
